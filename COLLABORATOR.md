# Collaborators Welcome

VOL is not so much a finished language as it is **a starting point for developing ideas together**.

Rather than having me implement every feature and lead every part of the project, I hope that people interested in VOL's ideas will interpret and improve them in their own ways. Everything from small fixes to rethinking the language design, improving the interpreter, or creating a new implementation is welcome.

## What You Are Free to Do

- Fork the repository and develop it independently
- Improve or redesign the syntax, type system, and execution model
- Build interpreters, compilers, tools, documentation, and examples
- Bring VOL's ideas to other languages or platforms
- Create experimental versions that take a different direction
- Submit proposals to this repository through Issues or Pull Requests

You do not need the original author's prior permission. This project is released under the MIT License, so you may use, modify, and distribute it as long as you comply with the license terms.

## How to Contribute

There is no required contribution format.

- If you are not ready to implement an idea, open an Issue and share it.
- For a small improvement, feel free to open a Pull Request directly.
- For a major change in direction, you may first explain the intent and design in an Issue.
- If your direction does not fit the original repository, or you want to develop it independently, feel free to fork it.

Contributions do not need to be polished. Questions, unsuccessful experiments, and disagreements with the design can all help the project evolve.

## Project Direction

VOL's central idea is to describe the elements of a program, whenever possible, through the consistent perspective of **creating, connecting, and evaluating Values**.

That does not mean the current syntax and implementation are definitive. Bold changes are welcome when they express the core philosophy more simply and clearly. Testing and developing good ideas matters more than preserving the existing design.

## Maintenance and Responses

The original author cannot promise to implement every proposal or review it quickly. If a response or merge is delayed, there is no need to put the project on hold. Please continue developing it in whatever way you consider most appropriate, including through a fork, a new implementation, or a separate release.
